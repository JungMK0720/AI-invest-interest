# FinMATE 보조 텍스트 모델

FinMATE에는 두 개의 작은 학습 모델이 있습니다. 둘 다 **학습을 돕는 보조 기능**이며, 투자 성향 등급·상품 적합성 판정·매매 권유에는 쓰이지 않습니다. 성향 등급은 언제나 서버의 규칙 엔진(`ProfileClassifier`)이 결정합니다.

| 모델 | 하는 일 | 화면 |
|---|---|---|
| 자유 서술 성향 신호 `style-signal` | 사용자가 쓴 투자 생각에서 5단계 성향과 관심사 태그 9종을 추정해 **설문과 다른 신호**가 있는지 알리고, 태그에 맞는 학습 개념을 추천 | 진단 마지막 단계(선택), 결과 화면, 모델 실험실 |
| 질문형 용어 검색 `term-retrieval` | 용어 이름을 몰라도 "회사가 버는 돈에 비해 주가가 몇 배인지 보는 숫자" 같은 질문으로 관련 용어를 찾음 | 용어 사전 검색, 모델 실험실 |

## 재현

```bash
python3 ml/train.py                                   # 학습·평가·내보내기 (약 20초)
python3 -m unittest discover -s ml -p 'test_*.py'     # 파이프라인 회귀 테스트
cd backend && mvn test                                # Java 추론이 Python 정답과 일치하는지 포함
```

Python 표준 라이브러리만 씁니다. 외부 패키지, 네트워크, API 키, 개인 데이터가 필요 없고 seed가 고정되어 있어 같은 결과가 나옵니다. 사용자 요청마다 Python을 호출하지 않습니다. 학습 결과는 JSON으로 내보내고 Spring Boot가 기동할 때 읽습니다.

## 구조

```
ml/
├── train.py                 # 학습·평가·내보내기 진입점
├── test_pipeline.py         # 데이터 분리, 결정성, 기준선 대비 성능, 정답 재현 테스트
├── finmate_ml/
│   ├── features.py          # 정규화·문자 2~4그램·벡터화 (Java TextFeatures와 동일 규칙)
│   ├── corpus.py            # 문장 조각 라이브러리 → 라벨 균형 학습 문장 생성기
│   ├── style.py             # softmax 로지스틱 회귀 + 태그별 로지스틱 회귀, 보류 규칙
│   ├── retrieval.py         # 필드별 TF-IDF 코사인 가중합 + 용어명 가산점, 격자 탐색
│   └── metrics.py           # 정확도·macro F1·±1등급·보정 오차·다중 라벨 지표
├── data/
│   ├── style_fragments.json      # 생성기 재료(목적·손실 반응·기간·경험·여력 + 태그)
│   ├── style_dev.jsonl           # 사람이 쓴 개발 문장 40개 (하이퍼파라미터 선택 + 최종 학습)
│   ├── style_holdout.jsonl       # 사람이 쓴 보류 문장 115개 (평가 전용, 태그 라벨 포함)
│   ├── style_offtopic_dev.jsonl  # 주제와 무관한 문장 30개 (보류 규칙 조정)
│   ├── style_offtopic_holdout.jsonl # 주제와 무관한 문장 20개 (보류 규칙 평가 전용)
│   └── term_queries.jsonl        # 용어 검색 질문 147개 (dev 61 / test 86)
└── reports/
    ├── evaluation.json           # 전체 평가 보고서(혼동행렬·오답 목록 포함)
    └── style_corpus_sample.jsonl # 생성 문장 예시 60개
```

내보내는 파일

- `backend/src/main/resources/ml/style-model.json` — 성향·태그 가중치, 온도, 보류 기준
- `backend/src/main/resources/ml/term-model.json` — IDF 표, 필드 가중치, 가산점, 원천 용어 JSON의 SHA-256
- `backend/src/main/resources/ml/model-card.json` — `GET /api/ml/models`가 그대로 보여 주는 모델 카드
- `backend/src/test/resources/ml/golden-predictions.json` — Java `MlParityTest`가 문장·질문마다 비교하는 정답

## 1. 자유 서술 성향 신호

### 학습 데이터를 만든 방법

실제 사용자 문장을 모을 수 없는 상황에서 40문장으로 학습하면(v1) 새로운 표현에 약했습니다. 그래서 설문 문항과 같은 축(목적·손실 반응·기간·경험·여력)으로 **문장 조각 라이브러리**를 만들고, 각 조각에 설문과 같은 0~100 위험 수용 점수를 붙였습니다.

1. 페르소나의 목표 점수를 고른다.
2. 목적·손실 반응 중 하나 이상과 기간·경험·여력 일부를 고르고, 목표 점수에 가까운 조각일수록 높은 확률로 뽑는다. 사람이 늘 일관되지는 않으므로 먼 조각도 낮은 확률로 섞인다.
3. **라벨은 실제로 뽑힌 조각 점수의 가중 평균**으로 정한다(목표 점수가 아님). 문장 내용과 라벨이 어긋나지 않게 하기 위해서다. 경계는 규칙 엔진과 같다(80/65/45/25 초과).
4. 라벨별 300문장씩, 총 1,500문장을 seed 고정으로 만든다.

평가용 보류 문장 115개는 생성기와 별도로 사람이 다른 표현으로 썼고, 학습 재료와의 최대 문자 4그램 자카드 유사도가 0.26으로 누수가 없음을 테스트로 확인합니다.

### 모델과 하이퍼파라미터 선택

- 특징: 소문자화 후 한글·영문·숫자만 남긴 문자 2~4그램, `1+log(tf)` 후 L2 정규화
- 성향: 5클래스 softmax 로지스틱 회귀(SGD, L2). epoch·L2는 **개발 문장 40개의 정확도**로 선택(epoch 5, L2 0.003)
- 확신도 보정: 개발 문장 음의 로그우도를 최소화하는 온도 선택(T = 0.4)
- 보류 규칙: 근거 조각(어느 성향이든 |가중치| ≥ 0.3)이 6개 미만이거나 확신도 0.3 미만이면 `INSUFFICIENT`. 주제 무관 개발 문장 90% 이상을 보류하면서 투자 서술의 판단 비율 75% 이상을 유지하는 조합 중 정확도가 가장 높은 것을 골랐습니다.
- 관심사 태그 9종: 원금 보전 중시, 단기 자금 필요, 장기 투자 가능, 고수익 추구, 손실 경험, 투자 경험 부족, 레버리지·파생 관심, 현금흐름 선호, 쏠림·추격 매수 신호. 태그별 로지스틱 회귀(양성 가중치로 불균형 보정), 기준 0.5
- 최종 모델은 생성 문장 1,500개 + 개발 문장 40개(가중치 3)로 학습

### 개인정보

진단 화면에서 받은 자유 서술 **원문은 저장하지 않습니다.** 추정 상태·등급·확신도·태그·모델 버전만 진단 스냅샷에 남깁니다.

## 2. 질문형 용어 검색

- 용어마다 세 필드를 따로 벡터화합니다: 이름(용어·정식 명칭·영문·별칭), 정의, 본문(설명·주의)
- 점수 = Σ 필드 가중치 × 코사인 유사도 + 용어명 가산점(질문에 용어명이 그대로 있으면 0.2, 별칭만 있으면 0.1). 영문 약어는 단어 단위로만 비교해 `IV`가 `derivative`에 걸리지 않게 했습니다.
- 학습 대상: 247개 용어의 IDF 표, 그리고 dev 질문 61개로 격자 탐색한 필드 가중치(이름 1.5 · 정의 1.5 · 본문 1.0)와 가산점
- **문서 벡터는 Java가 DB의 공개 용어로 만듭니다.** 관리자가 용어를 게시·비공개 처리하면 이벤트로 인덱스를 다시 만들어 재학습 없이 바로 반영됩니다. IDF에 없는 새 조각은 IDF 최댓값으로 취급합니다.

## 한계

- 성향 모델의 학습 문장 대부분은 실제 사용자 기록이 아닌 생성 문장입니다. 실제 사용자 문장에서는 정확도가 다를 수 있습니다.
- 보류 문장 115개는 한 사람이 써서 문체가 제한적입니다. 출시 전에는 동의를 받은 실제 문장으로 다시 평가해야 합니다.
- 반어·부정처럼 문맥이 필요한 표현, '~하고 싶어요' 같은 흔한 어미가 많은 짧은 잡담(주제 무관 개발 문장 30개 중 3개)은 잘못 분류될 수 있습니다.
- 용어 검색은 의미 임베딩이 아니라 문자 조각 일치에 기반하므로, 용어 설명과 전혀 다른 단어로 말한 질문은 놓칠 수 있습니다.
- 모든 숫자는 위 평가셋에만 해당하며, 투자 적합성이나 실제 고객 성능을 입증하지 않습니다.
