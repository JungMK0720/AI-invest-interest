# 06. 1차 Agile 검토 및 다음 세션 인계

## 결론

접근 방향은 타당하다. 현재 기획은 기능을 더 늘리는 단계가 아니라 **1차 범위를 고정하고, 진단 → 규칙 기반 성향 판정·LLM 근거 설명 → 탐색 카테고리 → 예시 상품 탐색의 한 세로 슬라이스를 완성하는 단계**다. 비교·포트폴리오·관리자 기능을 2차 Agile로 넘기는 판단도 적절하다.

이번 검토에서 다음 네 가지를 보완했다.

1. P0와 P1을 화면·ERD·API에서 분리했다.
2. AI 분석의 입력·출력·검증 경계를 정의했다.
3. 로그인 사용자 식별자를 요청 본문에서 받지 않도록 API 계약을 정리했다.
4. AI 실패, 권한 오류, 빈 상품 목록을 인수 조건과 예외 흐름에 포함했다.

추가 감시 결과, 현재 구현의 실제 기준인 5단계 성향·1~6 내부 위험등급·LLM 설명 폴백을 기준 문서에 통합했다. 상세 감사와 이후 작업은 [08-supervisor-review-and-plan.md](08-supervisor-review-and-plan.md)에 기록한다.

## 다음 세션 작업 순서

1. 제출용 파일을 dbdiagram.io와 Swagger Editor에서 시각·문법 검증한다.
2. S1~S6 와이어프레임을 제작한다. 각 화면에 입력·버튼·결과 필드를 넣고, 미응답·LLM 설명 폴백·데이터 준비 실패·빈 목록 상태를 표시한다.
3. 00/01/02와 와이어프레임 캡처를 프로젝트 기술서 PDF에 넣는다.
4. 발표용으로 “왜 범위를 여기서 닫았는가”와 “2차 Agile 확장 지점”을 한 장으로 요약한다.

## 2차 Agile 시작 조건

1차의 P0 인수 조건이 검증되고 제출물 3종이 완성된 뒤 시작한다. 시작 시에는 다음 순서가 안전하다.

1. 상품 비교(S7)
2. 가상 포트폴리오(S8)
3. 관리자 질문·상품 관리(S9~S10)
4. 자연어 입력·진단 추이·실시간 금융 데이터

2차 착수 전까지는 현재 문서의 P0 범위를 다시 넓히지 않는다.
