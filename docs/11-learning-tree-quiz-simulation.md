# 11. 개념 트리·확인 문제·모의투자 고도화

## 문제 정의

10번 문서에서 학습 콘텐츠를 5단계(한 문장 개념 → 구조 그림 → 실제 데이터 → 과거 사례 → 확인 퀴즈)로 설계했지만, 실제 구현은 평면 목록 18개와 전 개념 공용 확인 문제 1개에 머물러 있었다. 세 가지 문제가 있었다.

1. **깊이가 없다.** 개념이 한 줄로 나열되어 있어 "채권 안에 듀레이션이 있다"는 관계가 화면에 없었다. 개념 수를 늘릴수록 목록이 길어지기만 했다.
2. **확인 문제가 학습 도구가 아니었다.** 문항이 하나뿐이고 모든 개념에 같은 것이 나왔으며, 정답 판정이 클라이언트의 문자열 비교(`startsWith("상품설명서")`)였다. 화면 소스에서 정답이 보였고 오답 해설이 없었다.
3. **읽기만 하고 끝난다.** "금리가 오르면 채권 가격이 내린다"를 읽어도 얼마나 내리는지 감이 오지 않는다. 숫자를 직접 움직여 볼 수단이 없었다.

## 확정 설계

### 개념 트리 (3단계)

개념을 `대분류 → 핵심 개념 → 세부 개념` 3단계로 재구성했다. 총 59개(대분류 4, 핵심 23, 세부 32)다.

| 대분류 | 다루는 것 | 핵심 개념 |
|---|---|---:|
| 투자의 기초 원리 | 상품 종류와 무관하게 공통인 다섯 축 | 5개 (하위 14) |
| 자산군과 상품 구조 | 돈의 흐름과 위험 발생 지점 | 9개 (하위 12) |
| 파생상품과 레버리지 | 손실이 원금을 넘는 영역 | 4개 (하위 6) |
| 투자자 보호와 판단 | 제도가 지켜 주는 것과 아닌 것 | 5개 |

화면에서 하위 개념은 **두 단계로 제어**한다.

- **노드별 캐럿(▸/▾)**: 그 가지 하나만 펼치고 접는다.
- **상단 토글 "세부 개념까지 보기"**: 3단계 전체를 트리에서 켜고 끈다. 선택은 `localStorage`에 남아 다음 방문에도 유지된다.

검색어를 넣으면 일치하는 노드와 그 조상만 남기고 접힘 상태를 무시해 전부 펼친다. 검색 결과가 접혀 있어 보이지 않는 것이 트리 UI의 가장 흔한 실패이기 때문이다.

트리는 `GET /learning/tree` 한 번으로 전체를 받고 이후 펼침·접힘은 클라이언트에서만 처리한다. 59개 정도에서는 노드마다 요청하는 것보다 단순하고 빠르다.

### 콘텐츠 구조

개념 하나는 다음을 가진다. 출처(`sourceName`/`sourceUrl`)가 없으면 **기동 시점에 예외를 던져 배포가 실패한다.**

| 항목 | 역할 | docs/10의 5단계 대응 |
|---|---|---|
| `oneLiner` | 한 문장 정의 | 1단계 |
| `diagramKey` | 구조 그림(돈의 흐름·위험 지점) | 2단계 |
| `explanation` | 문단 배열 | 1~2단계 |
| `keyPoints` | 확인해야 할 것 | 3단계 |
| `misconception` | 자주 하는 오해 | — |
| `checklist` | 상품에서 확인할 문서·항목 | 5단계 |
| `quiz` | 확인 문제 | 5단계 |
| `simulationId` | 실험할 모의투자 | 3단계 대체 |

콘텐츠는 `backend/src/main/resources/learning/concepts.json`에 둔다. 콘텐츠 개정을 코드 변경과 분리하기 위해서이고, 이 JSON 스키마가 그대로 docs/10의 `concepts`·`content_revisions` 테이블로 옮겨진다.

4단계(과거 사례)는 아직 없다. 실데이터 수집이 붙기 전까지는 채울 근거가 없기 때문이다.

### 확인 문제

75문항 225선택지로 확장했다. 설계 원칙 세 가지를 두었다.

1. **정답은 서버에만 있다.** `GET .../quiz`는 선택지 라벨만 내려주고, 채점은 `POST .../quiz/grade`에서만 한다. 화면 소스에서 정답이 보이면 확인 문제가 동작하지 않는다.
2. **모든 선택지에 해설이 필요하다.** 정답뿐 아니라 오답에도 왜 틀렸는지를 적는다. 이 규칙은 카탈로그 로드 시점에 검증하며 위반하면 기동이 실패한다.
3. **점수보다 다음 행동을 남긴다.** 채점 응답의 `summary`는 점수 자체가 아니라 무엇을 다시 볼지를 말한다. 높은 점수가 투자 적합성으로 오인되지 않게 한다.

미응답(`selectedIndex = -1`)과 범위를 벗어난 인덱스는 오답으로 처리하고 400을 내지 않는다. 한 문항을 건너뛴 것이 요청 전체의 실패가 되면 학습이 끊긴다.

### 모의투자

**실제 주문이 아니라, 개념 하나가 돈에 어떻게 작용하는지 실험하는 도구**로 정의했다. "삼성전자를 100주 산다"가 아니라 "금리가 1%p 오르면 내 채권이 얼마나 떨어지는지 본다"이다. 이 정의가 중요한 이유는, 종목 매매 흉내를 내면 교육 서비스가 아니라 투자 권유로 읽히기 때문이다.

11개 시나리오를 구현했다.

| 시나리오 | 질문 | 계산 |
|---|---|---|
| `price-path` | 기대수익률이 같아도 결과가 같을까? | 로그정규 월 경로, MDD |
| `dca-vs-lumpsum` | 같은 돈을 언제 넣느냐가 결과를 바꿀까? | 동일 경로에 두 전략 적용 |
| `bond-rate-shock` | 금리 1%p에 채권은 얼마나 떨어질까? | 현금흐름 할인, 듀레이션·볼록성 |
| `fee-drag` | 작아 보이는 보수가 오래가면? | (1+r)(1-f) 복리 |
| `etf-tracking` | 지수는 올랐는데 내 수익은 왜 다를까? | 보수·추적오차·괴리·스프레드 단계 차감 |
| `diversification` | 상관계수가 얼마일 때 분산이 의미 있을까? | σp 공식 + 촐레스키 상관 경로 |
| `liquidity-exit` | 급하게 팔면 얼마를 손해 볼까? | 스프레드 + 참여율 제곱근 충격 |
| `leverage-decay` | 2배 상품은 정말 2배일까? | 일별 재조정 복리, 변동성 손실 |
| `option-payoff` | 사는 쪽과 파는 쪽은 어떻게 다를까? | 만기 손익 곡선, 손익분기점 |
| `futures-margin` | 얼마나 움직이면 추가 납입일까? | 일일정산, 유지증거금 미달 탐지 |
| `deposit-inflation` | 예금 이자는 물가를 이겼을까? | 세후 복리 ÷ 물가 |

설계 판단 세 가지.

- **계산은 전부 서버에서 한다.** 클라이언트는 폼 생성과 표시만 한다. 입력 명세(min/max/기본값)도 서버가 내려주므로 시나리오를 추가해도 화면 코드가 바뀌지 않는다.
- **seed로 결과를 고정한다.** 같은 입력·같은 seed면 항상 같은 결과가 나온다. docs/09의 결과 재현성 원칙을 학습 도구에도 적용한 것이고, 발표에서 같은 화면을 다시 만들 수 있어야 하기 때문이다. 대신 "다른 시장 상황 보기"로 seed를 재추첨할 수 있다.
- **한 번의 결과를 법칙으로 읽지 않게 만든다.** 이 도구의 가장 큰 오용이 "한 번 돌려 보니 벌었다"이다. 그래서 난수 시나리오에는 seed 재추첨 버튼을 두고, 결과의 `lessons`에 "같은 가정에서도 결과가 달라진다"를 명시한다.

잘못된 입력은 400을 내지 않고 명세 범위로 자른 뒤 실제 적용값을 `echo`로 돌려준다. 숫자 하나를 잘못 넣었다고 실험이 끊기면 안 된다.

## 실제 금융 구조와의 일치 검증

시뮬레이션이 "그럴듯한 숫자"가 아니라 실제 구조를 재현하는지 테스트로 고정했다.

- 표면금리 = 시장금리인 채권은 정확히 액면가에 가격이 매겨진다 (10,000,000원)
- 금리가 오르면 채권 가격이 내리고, **만기가 길수록 낙폭이 크다**
- 듀레이션 근사(-8.09%)와 실제 가격 변화(-8.11%)의 차이가 볼록성으로 설명된다
- 상관계수가 1이면 분산으로 줄어드는 변동성이 **정확히 0**이 된다
- 급하게 팔수록 현금화 비용이 커진다
- 변동성이 있으면 레버리지 결과가 단순 배수보다 **항상 낮다**
- 콜옵션 매수의 손익분기점 = 행사가 + 프리미엄
- 물가가 세후금리보다 높으면 실질 구매력이 줄어든다

## 안전장치

이 화면은 교육 콘텐츠이므로 다음을 지킨다.

- 모든 학습·모의투자 응답에 고지 문구를 포함한다. 화면에서도 항상 노출한다.
- 모의투자 결과에 `assumptions`(계산에 사용한 가정)를 함께 내려주고 화면에 접이식으로 노출한다. 결과를 예측으로 오인하지 않게 하기 위해서다.
- 특정 상품명·종목명을 쓰지 않는다. 시나리오의 자산은 전부 "가정한 변동성과 기대수익률"로만 정의된다.
- 세금 개념은 "세후로 비교해야 한다"는 구조까지만 다루고 구체적 세율 판단은 공식 자료로 넘긴다.
- 학습 API는 로그인 없이 접근 가능하다. docs/09의 "재진단 제한과 무관하게 학습은 열려 있어야 한다"를 API 수준에서도 지킨다.

## Self-Reflection

모의투자의 숫자는 전부 가정값이다. 실제 시세가 아니므로 "이 상품이 이만큼 오른다"로 읽힐 여지를 남기지 않도록 자산에 이름을 붙이지 않았고, 가정을 항상 함께 노출한다. 실데이터를 붙이는 단계에서는 지연 시세 여부와 기준 시각을 화면에 표시해야 한다.

콘텐츠 정확성은 공개 자료(Investor.gov, FINRA, CME, 금융감독원·예금보험공사 등)를 근거로 작성한 교육용 요약이다. 개별 상품의 적합성 판단이나 세무·법률 자문으로 확장하지 않는다. 배포 단계에서는 `content_revisions`의 검수자 필드를 실제로 채우는 검수 절차가 필요하다.
