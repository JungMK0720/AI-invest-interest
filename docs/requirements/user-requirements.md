# 사용자 요구사항 (UR)

기준일: 2026-10-26. 제품의 중심은 **증권업과 상품 구조를 이해하는 학습**이다. 투자 성향 진단은 학습을 돕는 기존 기능으로 유지한다. 새 학습 요구는 계획이며 아직 구현하지 않았다.

UR은 사용자가 얻으려는 결과다. 구현 방법은 [FR](functional-requirements.md), 품질·검증 조건은 [NFR](nonfunctional-requirements.md)에 둔다. 기존 ID를 재사용하지 않는다.

## 증권업 학습으로 확장하는 요구

근거는 2026-10-26 사용자 방향이며, 실제 학습 효과는 아직 검증하지 않은 가설이다. 단계는 [학습 로드맵](../product/learning-roadmap.md)을 따른다.

| ID | 사용자 요구 | 우선순위 | 수용 기준 | 연결 | 상태 |
|---|---|---|---|---|---|
| UR-20 | 증권이 무엇이고 왜 필요한지, 증권회사가 어떤 일을 하는지 알고 싶다 | Must · 1단계 | 자금 조달·발행·유통, 투자자·기업·증권회사·거래소·예탁결제의 역할을 사례로 구분한다 | FR-27, NFR-14·15 | 계획 |
| UR-21 | 은행과 증권회사, 국내 1·2금융권을 짧게 구분하고 본 학습으로 넘어가고 싶다 | Should · 1단계 | 기관의 역할 차이를 간단히 설명하며 1·2금융권을 위험 순위로 오해하지 않는다 | FR-28, NFR-15 | 계획 |
| UR-22 | 현물에서 출발해 선물·옵션·증거금·파생상품을 순서대로 이해하고 싶다 | Must · 1단계 | 현물·기초자산·계약·권리/의무·손익·증거금·추가 납부를 연결하고 자기 말로 설명한다 | FR-29·30, NFR-02·15 | 계획 |
| UR-23 | 과거 차트를 보면서 그 시점에 판단하고 다음 결과와 비교해 보고 싶다 | Should · 2단계 | 결정 전에는 당시 공개 정보만 보이고, 결정 후 다음 구간 공개와 회고를 진행한다 | FR-31~33, NFR-16·17 | 계획 |
| UR-24 | 차트를 보기 어렵더라도 같은 데이터를 표로 읽고 판단하고 싶다 | Should · 2단계 | 차트와 같은 날짜·가격·단위·공개 범위의 표로 모든 결정·회고 과업을 수행한다 | FR-34, NFR-11 | 계획 |
| UR-25 | 예측 모델을 만든다면 단순 기준보다 나은지, 비용과 한계까지 확인하고 싶다 | Could · 선택 3단계 | 시간 순서 평가, 단순 기준선, 거래 비용, 실패 구간, 재현 설정이 함께 공개된다 | FR-35, NFR-18 | 계획 · 첫 배포 필수 아님 |

UR-20~25는 실계좌·실주문·수익 보장 요구를 추가하지 않는다. 성과는 단기 수익률보다 개념 설명, 판단 근거, 오류 수정, 재학습 여부로 평가한다.
