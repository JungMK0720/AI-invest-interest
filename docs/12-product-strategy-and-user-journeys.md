# 12. 사용자 문제·제품 전략·학습 여정

> 상태: 제품 기획 기준서 v1.0  
> 작성일: 2026-09-10  
> 범위: 발표용 MVP 이후의 학습형 금융상품 탐색·모의투자 연습 서비스

## 1. 제품 한 문장

FinMATE는 투자성향 등급을 받아 상품을 고르는 서비스가 아니라, 사용자가 상품의 돈의 흐름과 위험이 바뀌는 조건을 학습하고, 가정된 시나리오에 직접 입력해 본 뒤, 공식 자료를 확인할 수 있게 하는 금융 의사결정 학습 도구다.

사용자는 다음 질문에 답할 수 있어야 한다.

- 이 상품에서 돈은 어디에서 수익 또는 손실로 바뀌는가?
- 가격·금리·변동성·환율·시간·수수료·유동성 중 무엇이 결과를 바꾸는가?
- 입력한 가정이 어떤 계산을 만들었는가?
- 실제로 확인해야 할 설명서·공시·수수료·위험등급은 어디에 있는가?
- 모르는 상태에서 가입하거나 레버리지를 높이지 않으려면 무엇을 더 확인해야 하는가?

상품 설명과 학습은 열어 두되, 실제 가입·주문·상담은 각 금융기관의 최신 설명·적합성·적정성 절차와 공식 문서를 따른다. FinMATE는 특정 상품의 매수·매도, 목표가격, 미래 수익을 제시하지 않는다.

## 2. 문제 인식: 관찰, 사용자 진술, 가설을 분리한다

현재 대화에서 확인된 내용은 “안정형으로 분류되어 원하는 상품을 바로 보지 못했다”, “개념을 실제 상품에 연결하기 어렵다”, “확인 문제가 같은 내용이라 학습이 되지 않는다”는 문제 제보이다. 이는 모집단의 비율이나 시장 규모를 증명하는 인터뷰 결과가 아니므로 제품에서는 가설과 검증 방법을 함께 관리한다.

| 구분 | 현재 근거 | 제품 처리 | 검증 |
|---|---|---|---|
| 사용자 제보 | 안정형 사용자가 공격적 상품을 공부하고 싶음 | 등급과 학습 접근을 분리 | 제한 뒤 행동 사용성 테스트 |
| 구현 관찰 | 기존 확인 질문이 여러 개념에서 반복 | 개념별 문항·오답 이유·다음 행동 | 문항별 오답률·재시도율 |
| 제품 가설 | 구조 그림과 숫자 실험이 글만 읽는 것보다 메커니즘 이해를 높임 | 개념→그림→입력→결과→공식 자료 | 대조군과 사후 설명 비교 |
| 제품 가설 | 사용자는 상품명보다 결과를 바꾸는 변수를 먼저 알아야 함 | 상품명 없는 시나리오와 민감도 | 자유 답변에서 원인 변수 언급 |
| 미확인 | 초보자·파생상품 경험자의 적정 깊이 | 난이도와 선택 경로 제공 | 5~8명 인터뷰·태스크 테스트 |
| 미확인 | 실시간 최신성의 필요와 비용 수용 | 기준 시각·지연을 표시 | 실제 데이터 연결 전후 조사 |

“완벽한 이해”는 완료 조건으로 쓰지 않는다. 목표는 설명 가능한 판단 과정과 다음 확인 행동을 남기는 것이며, 이해도는 반복 평가와 행동 관찰로 검증한다.

## 3. 핵심 사용자와 Jobs-to-be-Done

### 3.1 상품을 처음 비교하는 초보 투자자

예금·주식·채권·펀드·ETF를 대략 들었지만 금리, NAV, 보수, 스프레드, 만기를 연결하지 못한다. 돈이 어떤 경로로 움직이고 언제 현금화되는지 이해하는 것이 일이다. 상품 홍보와 전문용어가 섞인 검색 결과 대신 자산군→상품→메커니즘의 계층, 한 문장 정의, 돈의 흐름 그림, 초급 문항, 공식 문서 체크리스트를 제공한다. 성공은 상품명을 외우는 것이 아니라 수익·손실을 움직이는 변수와 확인 문서를 말하는 것이다.

### 3.2 성향 제한과 지식 부족을 혼동하는 사용자

평가 횟수 제한이나 현재 성향 결과 때문에 고위험 상품을 바로 거래하지 못한다. 현재 등급을 임의로 바꾸지 않고도 구조와 위험을 공부하는 것이 일이다. 상태, 제한 근거, 다음 평가 가능 시점, 기관 확인 조건, 위험 카드, 가정 실험, 설명서 체크리스트를 분리해 제공한다. 학습 접근과 거래 가능 여부는 다르다.

실제 기관 정책은 동일하지 않다. KDB는 비대면 평가를 일일 최대 3회, 만 65세 이상 또는 장애가 있는 경우 1일 1회로 안내하고 5영업일 이내 재평가의 등급 상향을 2단계 이내로 제한한다. FinMATE의 월 1회는 금융권 공통 규정이 아니라 제품 정책이다.

### 3.3 이론을 숫자로 확인하려는 학습자

“금리가 오르면 채권 가격이 내린다”를 읽었지만 크기를 모른다. 가상 입력을 바꾸고 어느 줄이 바뀌었는지 확인하는 것이 일이다. 가정·공식·결과·민감도·다른 경로를 나란히 보여 준다. 성공은 결과 금액보다 원인 변수를 설명하는 것이다.

### 3.4 후순위 사용자

경험자는 심화 개념과 원문을 빠르게 확인하고, 교육자·멘토는 같은 seed 시나리오를 재현한다. 콘텐츠 검수자는 원문·기준일·버전·계산 가정을 검수한다. 이들은 일반 사용자와 다른 운영자 흐름이며 개인정보 동의가 필요하다.

## 4. 핵심 약속

### 메커니즘을 상품명보다 먼저

1. 자산군: 주식, 채권, 현금성, 부동산·리츠, 금·원자재
2. 상품 포장: 개별 주식, 채권형 펀드, ETF, MMF, 리츠, 예금
3. 메커니즘: 소유권, 이자·쿠폰, 임대·배당, 가격 차이, 환매, 파생계약, 차입, 증거금, 일일정산
4. 위험 축: 시장가격, 금리, 신용, 환율, 유동성, 비용·세금, 레버리지, 운영·법적 조건

레버리지는 노출 확대 메커니즘이고, 마진은 상품에 따라 증권 담보대출 또는 선물·옵션의 이행보증금이다. CME는 선물 마진이 기초자산 계약금이 아니며 초기·유지 증거금과 마진콜이 구분된다고 설명한다.

### 학습과 거래 권한을 분리

- 학습 가능: 모든 개념·구조 그림·가정 시나리오
- 추가 확인 필요: 설명서·위험등급·비용·유동성·기간
- 기관 절차 필요: 적합성·적정성·투자자성향·숙려기간
- 거래 가능 여부: FinMATE가 결정하지 않고 금융기관이 안내

### 모든 결과에 원인과 한계를 붙임

입력(원금·기간·변수), 계산(공식·규칙), 관찰(손익·낙폭·비용·마진콜), 의미와 한계(빠진 세금·체결·실데이터)를 함께 표시한다. 생성 경로 하나를 미래 수익 예측으로 읽지 못하게 고지하고 seed 재현과 다른 경로를 제공한다.

## 5. 넓은 범위와 작은 범위

| 축 | 범위 | 공통 질문 |
|---|---|---|
| 기초 원리 | 위험·수익, 변동성, 낙폭, 복리, 목적·기간 | 잃을 범위와 회복 시간은? |
| 전통 자산 | 주식, 채권, 예금·MMF, 펀드·ETF | 누가 무엇을 소유하고 어떤 현금흐름을 받나? |
| 실물·대체 | 부동산·리츠, 금·원자재, 환율 | 보관·임대·추적·환율·유동성은? |
| 파생·차입 | 선물, 옵션, 증거금, 일일정산, 레버리지, 롤오버 | 왜 작은 가격 변화가 큰 손익 또는 추가 납입이 되나? |
| 보호·판단 | 적합성, 설명서, 위험등급, 비용, 사기 신호, 편향 | 가입 전 어떤 근거를 확인하나? |

한 세션은 하나의 메커니즘을 끝까지 연결한다: 상황→한 문장→돈의 흐름 그림→변수 실험→개념 고유 문항→설명서에서 찾을 항목→회고. 예를 들어 채권은 금리·듀레이션·만기·신용등급·중도매도를, 옵션은 매수·매도 권리·의무·프리미엄·손익분기점을 질문한다.

## 6. 확인 질문 설계

개념마다 판단 단위가 다르다.

| 개념 | 질문 초점 | 오답 교정 |
|---|---|---|
| 채권 | 금리 상승과 중도매도 가격 | 만기 보유와 중도매도 혼동 |
| ETF | 시장가격과 NAV 괴리 | 항상 NAV와 같다는 오해 |
| 옵션 | 권리·의무·손익분기점 | 프리미엄을 보장수익으로 오해 |
| 선물·증거금 | 초기·유지 증거금·일일정산 | 계약 전체 가격의 선불금으로 오해 |
| 레버리지 ETF | 일일 목표와 누적 결과 | 장기 수익률도 정확히 배수라는 오해 |
| 리츠·부동산 | 실물 소유와 지분·임대 현금흐름 | 리츠 가격이 실물과 항상 같다는 오해 |
| 금·원자재 | 현물·선물·ETF의 추적·보관·롤 비용 | 모든 금 상품이 같은 결과라는 오해 |
| 비용 | 연 보수·거래비용의 복리 | 표시 수익률이 비용 차감 후라는 오해 |

문항 역할은 개념 확인, 변수 추론, 오해 교정, 문서 읽기, 이해 한계 확인으로 분리한다. 점수는 학습 안내에만 쓰며 “100점=투자 가능” 배지는 만들지 않는다. 현재 구현은 59개 계층 개념, 75개 개념별 문항, 선택지별 오답 해설을 갖지만 정답률이 실제 이해를 보장하지 않으므로 검증이 남아 있다.

## 7. 사용자 여정

### 첫 방문

목표·기간·걱정되는 위험을 입력한다. 이는 성향 재판정이 아니라 학습 경로 선택이다. 위험·수익→투자기간→채권/ETF→비용·유동성의 짧은 경로를 따라 구조, 문항, 모의실험, 공식 체크리스트를 거친다.

### 성향 제한

현재 상태·제한 근거·다음 평가 시점·기관 확인 조건을 분리해 본다. 구조 학습, 가정 실험, 공식 자료, 나중에 확인 중 하나를 선택한다. 고위험 상품명은 교육 맥락에서 볼 수 있지만 거래 화면으로 우회시키지 않는다.

### 포트폴리오 연습

/simulation에서 가상 원금과 기간을 넣고 교육용 주식·채권·현금성·금·리츠 바구니 비중을 정한다. 금리 상승·주식 하락·금 가격·환율·보수·매도 스프레드 충격을 선택한다. 자산별 기여도, 손익, 낙폭, 유동성 필요액, 비용, 목표기간 미달을 비교한다. 특정 실상품 주문은 없으며 로그인 전에는 seed 링크로, 로그인 후에만 진도를 저장한다.

## 8. 완성 제품의 모습

홈은 “상품 추천” 대신 목표·기간·걱정되는 위험을 받고 학습 경로를 제시한다. 개념 지도는 자산군과 메커니즘으로 연결되며, 각 카드에는 그림·변수 실험·고유 문항·공식 출처·기준일 자료가 있다. 포트폴리오 연습기는 한 변수만 바꾼 전후를 비교하고 수익률 순위가 아니라 위험 축별 원인을 설명한다. 실제 상품을 확인할 때는 설명서·공시·수수료·위험등급 체크리스트와 데이터 기준 시각을 보여 준다. 사용자는 “무엇을 사야 하나?” 대신 “무엇이 바뀌면 결과가 달라지고 어떤 자료로 확인할까?”에 답한다.

## 9. 구현 범위와 우선순위

### 현재 프로토타입

- 59개 계층 개념, 75개 개념별 문항, 11개 개념 시나리오
- 서버 채점·선택지 해설, 가정값·seed·고지
- /learning/tree, 개념·퀴즈·시뮬레이션 조회·실행
- 채권·수수료·ETF·분산·옵션·선물·레버리지 메커니즘 실험

### 이번 고도화에 반영한 범위

1. 5~8명 태스크 테스트를 위한 개념별 오답·중단 지점 구조
2. `/practice` 포트폴리오 바구니·충격·전후 비교 화면과 stateless API
3. DB 없이도 재현 가능한 가상 상품·시나리오·계산 모델 버전
4. 상품 식별자 대신 자산군·메커니즘·변수·의미를 연결하는 학습 출력

### 다음 배포 고도화

1. 공식 API·허용 문서, 기준일·지연·hash·원문 연결
2. 상품 식별자·위험등급·수수료·설명서 연결(추천 아닌 학습·비교)
3. 로그인 후 진도·오답노트와 개인 실험 저장
4. 콘텐츠 버전·출처 만료·계산식 운영 검수

실제 주문·계좌 연결, 단일 종목 신호, 검증되지 않은 실시간 랭킹, 데이터 계약 없는 크롤링은 뒤로 미룬다.

## 10. 대안 비교(Self-Consistency)

| 대안 | 메커니즘 교육 | 데이터 부담 | 권유 오해 | 확장성 | 판단 |
|---|---:|---:|---:|---:|---|
| 상품 카탈로그·추천 중심 | 낮음 | 높음 | 높음 | 중간 | 왜 변하는지 설명하지 못해 제외 |
| 개념·개별 실험 중심 | 높음 | 낮음~중간 | 낮음 | 높음 | 현재 발표·프로토타입 기반 |
| 포트폴리오 연습+출처·시점 자료 | 높음 | 중간~높음 | 통제 필요 | 높음 | 최종 제품 방향으로 채택 |

B(개념 실험)를 기반으로 C(포트폴리오 연습)를 추가하는 단계적 구조가 제품 목표와 가장 잘 맞는다.

## 11. Self-Reflection: 한계

- 문제는 현재 제보와 관찰에 기반한 가설이며 모집단 연구가 아니다. 출시 전 5~8명 태스크 테스트가 필요하다.
- 59개·75문항은 수량이지 이해 증거가 아니다. 자유 설명·공식 문서 찾기·며칠 후 재현을 측정해야 한다.
- 현재 모의투자는 가정값 기반이다. 실데이터 연결 시 기준 시각, 지연, 배당·세금·체결·환율·롤오버 포함 여부를 표시한다.
- 레버리지 누적 결과가 항상 단순 배수보다 낮다고 단정하지 않는다. 경로·변동성·리밸런싱·비용에 따라 달라진다. SEC Investor.gov도 일일 목표와 장기 결과가 크게 달라질 수 있다고 설명한다.
- 재진단 횟수·상향 제한은 기관·고객 조건별로 다르며 KDB 사례를 FinMATE 월 1회 정책과 혼동하지 않는다.
- 교육용 단순화 그림은 설명서의 모든 위험을 대체하지 않는다. 카드에 원문과 추가 확인 항목을 남긴다.
