# 13. 기능·비기능 요구사항과 Use Case Diagram

> 보존 문서: FinMATE 당시의 설계·검증 기록입니다. 현재 제품 방향은 [제품 비전](../product/vision.md), 현행 요구사항은 [문서 안내](../README.md)를 따릅니다. 본문의 완료 표시는 이번 정리 작업에서 재검증한 결과가 아닙니다. 코드 링크의 organization 저장소와 `main` 경로는 분리 후 목적지이며 원격 반영은 별도 확인이 필요합니다.
> 작성일: 2026-09-10  
> 기준: 현재 구현된 FinMATE 프로토타입 + 최종 배포를 위한 확장 설계  
> 목적: 발표용 범위(P0)와 제품화 범위(P1)를 같은 기준으로 추적하고, 기능 요구사항·비기능 요구사항·유스케이스·API·화면을 연결한다.

## 1. 시스템 경계와 제품 원칙

FinMATE는 금융상품을 대신 추천하거나 주문하는 서비스가 아니라, 사용자가 상품의 구조와 위험 변수를 학습하고 가정값으로 결과를 실험하는 학습 도구다. 진단 결과는 탐색의 출발점으로만 사용하며, 학습 접근 권한과 실제 거래 가능 여부를 분리한다.

시스템 안에는 사용자 화면, 규칙 기반 진단 엔진, 설명 생성기, 학습 콘텐츠 카탈로그, 교육용 계산 엔진이 있다. 실제 시세·공시·설명서는 외부 데이터 공급자에서 가져오며, 최종 배포 단계에서는 운영자가 출처와 버전을 검수한 뒤 공개한다.

다음 기능은 시스템 경계 밖으로 둔다.

- 실제 증권계좌 연결, 주문·체결·입출금
- 목표수익률·목표가격·매수/매도 신호의 생성
- 개인별 세무·법률·투자자문
- 금융기관의 적합성·적정성 판정 대행

### 발표용 P0 세로 슬라이스

`FR-01~08`은 기존 진단·상품 탐색 흐름이고, `FR-10~14`는 현재 고도화된 학습·모의투자 흐름이다. 발표에서는 두 흐름을 “진단 결과를 보는 경로”와 “등급과 무관하게 개념을 배우고 실험하는 경로”로 나누어 보여 준다. `FR-09`, `FR-15~19`는 배포형 확장으로 설명하고, `FR-20`은 명시적 제외 범위로 남긴다.

## 6. Use Case 상세 시나리오

### UC-04 답변을 제출하고 진단을 생성

1. 사용자가 활성 질문 버전과 답변을 제출한다.
2. 서버가 인증 사용자·필수 문항·선택지 ID·중복 제출 키를 검증한다.
3. 규칙 엔진이 점수·5단계 성향·탐색 카테고리를 계산한다.
4. AI 설명 생성기가 입력 답변과 규칙 결과를 받아 근거를 만든다.
5. AI가 실패하거나 정책 검사를 통과하지 못하면 버전이 있는 템플릿을 사용한다.
6. 서버가 결과·근거 상태·콘텐츠 버전·계산식 버전을 저장하고 응답한다.

예외: 문항 누락은 400, 진단 제한은 409, AI 지연은 폴백 완료, 데이터 버전 불일치는 503과 재시도 안내로 처리한다.

### UC-10~UC-13 학습·실험 흐름

사용자는 성향 결과와 상관없이 개념 트리에서 자산군→상품 구조→메커니즘으로 이동한다. 개념 카드에서 한 문장 정의, 돈의 흐름 그림, 핵심 변수, 오해, 공식 출처를 확인한 뒤 해당 개념 전용 문제를 푼다. 이후 금리·수수료·변동성·유동성·옵션·선물·레버리지 중 하나의 시나리오를 실행하고, 가상 포트폴리오에서는 자산 바구니와 충격을 바꿔 전후 결과를 비교한다. 모든 결과에는 입력·공식·seed·가정·한계가 남는다.

### UC-17~UC-19 실데이터·과거 자료 흐름

운영자가 허용된 공급자와 수집 주기를 등록하면 수집기가 원문과 기준 시각을 저장하고 정규화한다. 검수자는 단위·누락·출처·저작권·위험 고지를 확인한 뒤 게시한다. 현재 데이터와 과거 스냅샷은 화면에서 별도 탭으로 제공하며, 최신값으로 과거 결과를 덮어쓰지 않는다. 공급자 장애나 출처 만료는 사용자에게 데이터 기준 시각과 상태를 표시한다.

## 8. 요구사항 추적성 및 완료 기준

발표 제출물은 다음 네 가지가 모두 연결되면 완료로 본다.

1. `docs/07-usecase.puml`의 각 P0 유스케이스가 이 문서의 FR·화면·API 중 하나 이상과 연결된다.
2. P0 화면에서 입력·성공·빈 상태·오류·폴백·면책 문구를 확인할 수 있다.
3. 학습·시뮬레이션 결과에 가정·seed·계산식 버전·출처 또는 “가정값” 표시가 있다.
4. `mvn test`, `npm run build`, `git diff --check`가 통과하고, 실데이터 미연동 범위가 발표자료에 명시된다.

최종 배포 완료 기준은 P0에 P1의 진도 저장, 출처 스냅샷, 과거 자료, 관리자 검수, 관측 지표를 추가한 뒤 NFR-01~14의 검증 증거를 남기는 것이다.

## 9. 설계 한계와 검증 계획

- 현재 사용자 문제는 제보와 구현 관찰에서 출발한 가설이므로 5~8명 태스크 테스트로 학습 완료율·오답 반복·모의실험 후 설명력을 확인한다.
- 59개 개념과 75개 문항은 콘텐츠 수량이지 이해의 증거가 아니다. 자유 설명, 공식 자료에서 확인할 항목 찾기, 며칠 뒤 재현을 함께 측정한다.
- 현재 실험기는 가정값 기반이다. 실데이터 단계에서는 지연·배당·세금·체결·환율·롤오버 포함 여부를 데이터 계약에 명시한다.
- 진단 횟수 제한은 금융권 공통 규정으로 단정하지 않고 FinMATE 정책과 기관별 안내를 분리해 표시한다.
