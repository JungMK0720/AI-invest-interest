# 01. 요구사항 정의 (Requirements)

> 보존 문서: FinMATE 당시의 설계·검증 기록입니다. 현재 제품 방향은 [제품 비전](../product/vision.md), 현행 요구사항은 [문서 안내](../README.md)를 따릅니다. 본문의 완료 표시는 이번 정리 작업에서 재검증한 결과가 아닙니다. 코드 링크의 organization 저장소와 `main` 경로는 분리 후 목적지이며 원격 반영은 별도 확인이 필요합니다.
> 기준 문서: [00-project-brief.md](00-project-brief.md)
> 상태: 확정(Fixed) — MVP(1차) 기준. 확장 항목은 [changelog.md](changelog.md)의 backlog 참고.
> 고도화 기준: 최종 배포형 기능/비기능 요구사항과 Use Case 추적은 [13-functional-nonfunctional-usecases.md](13-functional-nonfunctional-usecases.md)를 함께 본다. 이 문서는 발표용 P0의 상세 기준을 보존한다.

## 1. 시스템 액터 정의

PDF 예시(회의실 예약 서비스, p.17)의 액터 표 형식을 따른다.

| Actor 구분 | 주요 역할/행동 | 상세 설명 |
|---|---|---|
| 일반 사용자 | - 회원가입/로그인<br>- 진단 질문 응답<br>- 분석 결과 확인<br>- 탐색 카테고리·상품 조회 | - 로그인 후 진단을 시작하며, 완료 시마다 하나의 진단 이력(assessment)이 생성된다.<br>- 분석 결과에는 5단계 성향 분류와 판단 근거가 함께 제공된다.<br>- 1차에서는 내부 위험 필터를 통과한 카테고리의 예시 상품을 탐색한다. |
| 관리자 (2차) | - 진단 질문 관리(등록/수정/삭제)<br>- 금융상품 카테고리 관리<br>- 금융상품 정보 관리 | - 1차에서는 질문·상품을 시드 데이터로 제공한다.<br>- 2차에서 관리 화면과 API를 추가한다. |
| AI 분석 엔진 (내부 시스템) | - 답변 기반 설명 생성 | - 별도 로그인 주체가 아니다. 성향 점수·등급·카테고리 필터는 규칙 엔진이 결정하고, AI는 설명 문장만 생성한다. 호출 실패 시 템플릿으로 대체한다. |

## 2. 기능 요구사항 (Functional Requirements)

우선순위: **필수(P0)** = MVP에 반드시 포함, **선택(P1)** = 2차 확장 후보.

| ID | 기능 | 액터 | 우선순위 | 설명 |
|---|---|---|---|---|
| FR-01 | 회원가입 / 로그인 | 일반 사용자 | P0 | 이메일, 비밀번호 기반 |
| FR-02 | 진단 질문 목록 조회 | 일반 사용자 | P0 | 사전 등록된 활성 질문·선택지 조회 |
| FR-03 | 진단 답변 제출 | 일반 사용자 | P0 | 답변 제출 시 진단(assessment) 생성 |
| FR-04 | 투자 성향 분석 및 근거 생성 | 일반 사용자 (규칙 엔진·AI 엔진 처리) | P0 | 규칙 엔진이 점수·5단계 성향을 판정하고, AI 또는 템플릿이 근거 텍스트를 생성 |
| FR-05 | 분석 결과 조회 | 일반 사용자 | P0 | 성향 분류, 근거, 추천 카테고리 표시 |
| FR-06 | 탐색 카테고리 및 상품 목록 조회 | 일반 사용자 | P0 | 내부 위험 필터를 통과한 카테고리와 해당 카테고리의 사전 등록 예시 상품 목록 |
| FR-07 | 상품 상세 조회 | 일반 사용자 | P0 | 위험도, 예상 투자기간, 특징 |
| FR-08 | 상품 비교 | 일반 사용자 | P1 | 2~3개 상품 나란히 비교 |
| FR-09 | 가상 포트폴리오 저장/조회 | 일반 사용자 | P1 | 관심 상품을 담아두는 목록 |
| FR-10 | 진단 질문 관리 | 관리자 | P1 | 질문/선택지 등록·수정·삭제 |
| FR-11 | 상품·카테고리 관리 | 관리자 | P1 | 상품 등록·수정·삭제 |

> P0(FR-01~07)이 1차(MVP) 세로 슬라이스이며, 이번 3일 과제의 제출 대상이다.
> P1은 2차 Agile backlog다. 1차 UI 흐름·ERD·OAS에는 섞지 않고, 확장 지점만 문서에 남긴다.

## 3. P0 인수 조건 (Acceptance Criteria)

| 기능 ID | 완료 조건 |
|---|---|
| FR-01 | 유효한 이메일/비밀번호로 가입·로그인할 수 있고, 잘못된 입력은 오류로 표시된다. |
| FR-02 | 활성 질문과 선택지가 정해진 순서로 노출된다. |
| FR-03 | 모든 문항에 답한 경우에만 제출할 수 있으며, 제출 시 하나의 진단이 생성된다. |
| FR-04 | 분석 결과는 0~100점, `공격투자형/적극투자형/위험중립형/안정추구형/안정형` 중 하나, 판단 근거, 탐색 카테고리를 포함한다. 등급과 점수는 LLM이 임의로 바꿀 수 없다. |
| FR-05 | 본인의 진단 결과만 조회할 수 있고, LLM 설명 생성 실패 시 템플릿 근거로 결과가 표시된다. 문항·카테고리 데이터가 없을 때는 오류와 재시도 경로가 표시된다. |
| FR-06 | 탐색 카테고리와 그 카테고리에 속한 예시 상품 목록을 조회할 수 있다. 카테고리 위험등급은 과제용 내부 등급이며 실제 투자 권유 판단이 아니다. |
| FR-07 | 상품 상세에서 위험도, 예상 투자기간, 특징, 정보 제공 면책 문구를 확인할 수 있다. |

## 4. 비기능 요구사항 (Non-Functional)

- 결과는 "투자 자문·투자 권유"가 아니라 "탐색 정보 제공"임을 화면과 API 설명에 명시한다. (규제/오해 방지)
- 상품 데이터는 실시간 시세 연동 없이 사전 등록된 예시 데이터를 사용한다.
- 인증은 이메일/비밀번호 기반의 단순 로그인으로 한다 (OAuth 등 미포함).
- 로그인 사용자는 자신의 진단 결과만 조회할 수 있다.
- LLM 설명 생성 실패 시 원문 오류나 내부 프롬프트를 노출하지 않고 규칙 기반 템플릿으로 대체한다. 문항·카테고리 데이터가 준비되지 않은 경우에만 공통 503 오류와 재시도 경로를 사용한다.
- 선택지 점수, 배점, 개인 답변 원문, 프롬프트는 외부 응답과 일반 로그에 노출하지 않는다.
- 활성 질문의 배점 합은 100이고, 상품 카테고리 위험등급은 1~6 범위여야 한다.

## 5. 명시적 제외 범위

- 실제 증권계좌 연동, 실제 매수/매도
- 실시간 시세, 수익률 예측 모델
- 개인 맞춤 세무/법률 자문
- 관리자 회원가입 화면 (관리자 계정은 시드 데이터로 가정 — PDF 예시처럼 별도 회원가입 흐름을 만들 수도 있으나 MVP 범위에서는 생략)
- 1차 범위의 상품 비교, 포트폴리오, 관리자 CRUD 화면/API

## 6. 요구사항 ↔ 화면 ↔ API 추적성 (요약)

상세 매핑은 [02-user-flow.md](02-user-flow.md) §4, [04-api-design.md](04-api-design.md) 참고. 아래는 상위 추적표만 제공한다.

| 기능 ID | 관련 화면 | 관련 API (태그) |
|---|---|---|
| FR-01 | 회원가입/로그인 | auth |
| FR-02, FR-03 | 진단 진행 | questions, assessments |

| FR-08~FR-11 | 2차 Agile 화면 | 2차 Agile API |

## 7. MVP에서 명시하지 않는 것

- 5단계 성향과 1~6 카테고리 위험등급의 비교식은 과제용 내부 탐색 규칙이다. 이를 실제 금융기관의 적합성·적정성 판단 또는 투자 권유로 표현하지 않는다.
- LLM은 성향 판정, 점수 계산, 상품 선택의 주체가 아니다. 설명 생성 결과가 정책을 위반하면 템플릿으로 대체하는 것은 P1 보강 항목이다.
- 현재 인증 토큰은 데모용 메모리 저장소를 사용한다. 토큰 만료·폐기·다중 인스턴스 공유는 P1이다.
