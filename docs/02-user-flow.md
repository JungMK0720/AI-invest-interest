# 02. UI 흐름 (User Flow / Wireframe 설계 지침)

> 기준 문서: [01-requirements.md](01-requirements.md)
> 상태: 확정(화면 목록/흐름) — 실제 와이어프레임(캡처 이미지)은 Balsamiq/파워포인트로 별도 제작하여 최종 PDF에 삽입한다.
> **중요**: PDF p.5에 따라 "UI 흐름도는 반드시 PDF 파일 내에 화면 캡처로 존재해야 함". 이 문서는 그 와이어프레임을 만들기 위한 설계 근거다.

## 1. 화면 목록

| 화면 ID | 화면명 | 액터 | 관련 기능 | 단계 |
|---|---|---|---|---|
| S1 | 회원가입/로그인 | 일반 사용자 | FR-01 | 1차(P0) |
| S2 | 진단 시작 | 일반 사용자 | FR-02 | 1차(P0) |
| S3 | 진단 진행 (질문 응답) | 일반 사용자 | FR-02, FR-03 | 1차(P0) |
| S4 | 분석 결과·탐색 카테고리 | 일반 사용자 | FR-04, FR-05 | 1차(P0) |
| S5 | 탐색 카테고리·상품 목록 | 일반 사용자 | FR-06 | 1차(P0) |
| S6 | 상품 상세 | 일반 사용자 | FR-07 | 1차(P0) |
| S7 | 상품 비교 | 일반 사용자 | FR-08 | 2차(P1) |
| S8 | 가상 포트폴리오 | 일반 사용자 | FR-09 | 2차(P1) |
| S9 | (관리자) 질문 관리 | 관리자 | FR-10 | 2차(P1) |
| S10 | (관리자) 상품 관리 | 관리자 | FR-11 | 2차(P1) |

## 2. 사용자 흐름 (일반 사용자, 핵심 시나리오)

```
S1 회원가입/로그인
  └→ S2 진단 시작 (진단 이력이 있으면 "다시 진단하기" 옵션도 노출)
       └→ S3 진단 진행 (질문 목록 순차 응답, 마지막 문항에서 "제출" 버튼 활성화)
            └→ (제출) → AI 분석 처리 (로딩)
                 └→ S4 분석 결과 (5단계 성향 + 점수 + 근거 문장 + 탐색 카테고리)
                      └→ S5 탐색 카테고리·상품 목록 (내부 위험 필터 기준)
                           └→ S6 상품 상세 (위험도/예상기간/특징/면책 문구)
```

### 예외 흐름

- S3에서 미응답 문항이 있으면 "제출" 버튼 비활성화, 안내 문구 표시.
- S3 제출 후 LLM 설명 생성에 실패하면 템플릿 근거로 결과를 완료하고 `TEMPLATE` 상태를 표시한다. 사용자는 별도 재시도 없이 핵심 결과를 확인할 수 있다.
- 문항·카테고리 데이터가 준비되지 않아 분석할 수 없으면 공통 오류 안내 → 답변을 유지한 채 재시도 버튼을 제공한다.
- 로그인 실패 또는 권한 없는 진단 결과 접근 시 오류 안내 후 로그인 화면으로 이동.
- S5에서 조건에 맞는 상품이 없을 경우 "조건에 맞는 상품이 없습니다" 빈 상태 화면 표시.

## 3. 2차 Agile 확장 흐름

```
S6 상품 상세
  ├→ S7 상품 비교 (2~3개 담긴 상품 나란히 표시)
  └→ S8 가상 포트폴리오 (담기, 목록, 삭제)

S9 질문 관리
  - 질문 목록 조회 → + 버튼으로 신규 질문/선택지 등록 패널 노출 → 저장
  - 목록의 질문 클릭 → 수정 패널 노출 → 저장/삭제

S10 상품 관리
  - 카테고리별 상품 목록 조회 → + 버튼으로 신규 상품 등록 패널 노출 (이름/카테고리/위험도/예상기간/설명 입력) → 저장
  - 목록의 상품 클릭 → 수정 패널 노출 → 저장/삭제
```

> S7~S10은 1차 제출용 UI 흐름도에 포함하지 않는다. 2차 착수 시 요구사항과 함께 다시 확정한다.

## 4. 화면 ↔ API 매핑 (UI-API 일치 확인용, 평가 기준 핵심)

| 화면 | 주요 동작 | 필요한 API | 단계 |
|---|---|---|---|
| S1 | 회원가입 | `POST /auth/signup` | 1차 |
| S1 | 로그인 | `POST /auth/login` | 1차 |
| S2, S3 | 질문 목록 조회 | `GET /questions` | 1차 |
| S3 | 답변 제출 (진단 생성·분석) | `POST /assessments` | 1차 |
| S4 | 분석 결과 조회 | `GET /assessments/{assessmentId}` | 1차 |
| S4 | 탐색 카테고리 조회 | `GET /assessments/{assessmentId}/recommendations` | 1차 |
| S5 | 탐색 카테고리의 상품 목록 조회 | `GET /products?categoryId=...` | 1차 |
| S5 | 전체 카테고리 목록 조회(필터 보조) | `GET /product-categories` | 1차 |
| S6 | 상품 상세 조회 | `GET /products/{productId}` | 1차 |
| S7~S10 | 비교·포트폴리오·관리 기능 | 2차 착수 시 정의 | 2차 |

이 표의 모든 API는 [04-api-design.md](04-api-design.md)에 1:1로 정의되어야 한다 (평가 기준: "UI에서 필요한 API 누락" 방지).

## 5. 와이어프레임 제작 체크리스트 (Day 1 작업용)

- [ ] S1~S6 와이어프레임을 Balsamiq 또는 파워포인트로 제작
- [ ] 각 화면에 버튼/입력필드 등 구체적 UI 요소 표기 (평가 기준: "화면 구성 요소 구체화")
- [ ] 화면 간 이동을 화살표로 표시
- [ ] 미응답, LLM 설명 폴백, 데이터 준비 실패, 빈 상품 목록의 예외 상태를 최소 1개 이상 화면에 표시
- [ ] 캡처 이미지를 프로젝트 기술서 PDF에 삽입
