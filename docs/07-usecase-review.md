# 07. Use Case Diagram 검토 및 보완

> 2026-09-10 갱신: 현재 제품 범위(개념별 학습·메커니즘 시뮬레이션·교육용 포트폴리오·실데이터 운영)를 포함한 최신 기능/비기능 요구사항과 20개 유스케이스의 기준은 [13-functional-nonfunctional-usecases.md](13-functional-nonfunctional-usecases.md)이다. 이 문서는 초기 P0/P1 검토 기록으로 보존한다.

## 검토 결론

기존 `usecase.png`는 주요 액터와 기능을 폭넓게 담았다는 점은 좋지만, 그대로 1차 산출물로 사용하기에는 보완이 필요하다. 특히 1차(P0)와 2차(P1)가 한 화면에 섞여 있고, 일부 유스케이스 이름과 관계가 UML 의미와 맞지 않는다.

## 확인된 문제와 조치

| 확인 사항 | 문제 | 조치 |
|---|---|---|
| 범위 | 상품 비교·포트폴리오·관리자 기능이 1차 기능과 같은 레벨로 보임 | P0/P1을 별도 패키지로 분리 |
| 중복 | `진단을 시작한다`, `신규 진단을 시작한다`, `재진단을 시작한다`가 중복 | `진단을 시작한다` 하나로 통합. 신규/재진단은 시나리오로 처리 |
| 이름 | `재시도 결과를 제출한다`는 실제 동작과 다름 | `AI 분석을 재시도한다`로 정정하고 예외 시나리오로 분리 |
| AI 관계 | AI 분석 엔진이 사용자 기능처럼 독립 배치됨 | AI 분석 엔진을 `분석 근거 문장을 생성한다`에 연결하고 답변 제출의 `<<include>>`로 표현 |
| 관계 표기 | 일반 연관선에 방향 화살표가 많아 의존 관계처럼 보임 | 일반 액터-유스케이스 연결은 연관선으로, `<<include>>`만 점선 화살표로 표현 |
| 추적성 | 유스케이스 ID가 없어 요구사항과 대조하기 어려움 | UC-01~UC-13 ID를 부여하고 FR/S 화면과 매핑 |
| 시스템명 | 제목의 `&&`가 비표준적이고 서비스명이 불명확함 | `FinMATE - AI 투자 성향 진단 및 금융상품 탐색`으로 통일 |

## 관계 규칙

- UC-04 `진단 답변을 제출한다`는 UC-05 `분석 근거 문장을 생성한다`를 `<<include>>`한다.
- 성향 점수·5단계 성향·탐색 카테고리 필터는 규칙 엔진이 산출하고, UC-05는 그 결과와 실제 답변을 바탕으로 설명 문장만 생성한다.
- UC-06~UC-09는 사용자가 결과와 상품 정보를 탐색하는 독립 유스케이스다. 화면 이동을 모두 유스케이스 관계로 그리지 않는다.
- AI 오류 시 `AI 분석을 재시도한다`는 UC-05의 예외 시나리오이며, 별도 핵심 유스케이스로 세지 않는다.

## 보완본 사용 방법

PlantUML 원본은 [07-usecase.puml](07-usecase.puml)이다. 기존 PNG를 최종 PDF에 넣을 때는 이 원본으로 다시 렌더링한 이미지를 사용하고, 1차 발표 자료에는 P0 패키지가 먼저 읽히도록 배치한다.

## 2026-09-08 재검증

- `usecase.puml`을 PlantUML로 실제 렌더링해 기존 `usecase.png`(문제 있던 원본)와 육안 대조했다. 위 표의 7개 문제(범위 혼재, 중복, 오명명, AI 관계, 화살표 오용, 추적성, 시스템명)가 원본에 실제로 존재했고, 보완본에서 모두 해소됨을 확인했다.
- 추적성을 다이어그램 자체에서도 확인할 수 있도록 각 유스케이스 라벨에 `UC-01.`~`UC-13.` 번호를 직접 표기하고, 루트 `usecase.png`를 이 보완본으로 교체했다. 표로만 대조하지 않아도 다이어그램만 보고 FR/화면 매핑을 추적할 수 있다.
