# FinMATE 발표자료 전체 구성안

> 대상: 현재 13장 발표자료 + 플로우차트·와이어프레임 부록 8장  
> 권장 발표 시간: 5~7분  
> 핵심 흐름: 문제 → 사용자 → 해결 구조 → 실제 화면/API → 고도화 결과 → 확장 계획

## 1. 전체 발표 전략

발표는 기능 목록을 나열하는 방식보다 사용자가 겪는 문제를 먼저 제시하고, 그 문제를 해결하는 화면·API·계산 구조를 순서대로 보여 주는 방식이 좋다.

```text
사용자 문제
  ↓
FinMATE가 제공하는 학습 경험
  ↓
사용자 흐름과 Use Case
  ↓
화면과 API가 어떻게 구현하는가
  ↓
학습·모의투자 고도화 결과
  ↓
실데이터·운영·배포 확장
```

발표에서 계속 유지할 한 문장은 다음과 같다.

> FinMATE는 상품을 대신 추천하는 서비스가 아니라, 사용자가 상품의 구조와 위험 변수를 이해하고 가정값으로 실험하게 하는 학습 도구다.

## 2. 권장 본문 목차

5분 발표라면 본문은 10장으로 제한하고, API 상세·Requirements 추적·배포 계획은 부록으로 분리한다.

| 순서 | 슬라이드 제목 | 핵심 질문 | 권장 시간 |
|---:|---|---|---:|
| 1 | FinMATE | 무엇을 만드는가? | 15초 |
| 2 | 문제 정의 | 사용자는 왜 어려움을 겪는가? | 30초 |
| 3 | 서비스 범위와 핵심 사용자 | 누구에게 무엇을 제공하는가? | 30초 |
| 4 | 사용자 여정 | 사용자는 어떤 순서로 경험하는가? | 35초 |
| 5 | 학습 구조 | 상품을 어떻게 개념과 메커니즘으로 학습하는가? | 35초 |
| 6 | Use Case와 요구사항 | 기능과 품질 조건을 어떻게 설계했는가? | 40초 |
| 7 | API와 시스템 구조 | 화면 동작은 어떤 계약으로 연결되는가? | 45초 |
| 8 | 실제 화면과 와이어프레임 | 사용자는 무엇을 보게 되는가? | 50초 |
| 9 | 모의투자 연습기 | 고도화된 핵심 경험은 무엇인가? | 60초 |
| 10 | 안전장치와 확장 계획 | 지금의 한계와 다음 단계는 무엇인가? | 30초 |

총 발표 시간은 약 5분 30초다. 시연을 추가하면 7분 안팎으로 늘어난다.

## 3. 슬라이드별 구성

### 1. FinMATE

**화면에 넣을 것**

- 서비스명
- 한 줄 설명
- 발표자 정보

**말할 것**

“FinMATE는 투자 성향 진단 결과를 단순 추천으로 끝내지 않고, 금융상품의 구조와 위험 변수를 학습하고 직접 실험하게 하는 서비스입니다.”

표지에서 API 수, 기술 스택, 기능 목록을 설명하지 않는다.

### 2. 문제 정의

**화면에 넣을 것**

- 안정형으로 분류되어 원하는 고위험 상품을 공부하기 어려운 문제
- 상품 설명을 읽어도 금리·변동성·비용·레버리지가 결과에 어떻게 작용하는지 이해하기 어려운 문제
- 기존 확인 문제가 반복되어 학습 효과가 낮은 문제

**말할 것**

“거래를 허용해 달라는 요구와 상품을 공부하고 싶다는 요구는 다릅니다. FinMATE는 이 둘을 분리해 학습 접근은 열어 두고, 실제 거래 가능 여부는 금융기관 절차에 맡깁니다.”

### 3. 서비스 범위와 핵심 사용자

**화면에 넣을 것**

왼쪽에는 사용자, 오른쪽에는 제공 경험을 둔다.

```text
초보 투자자
  → 자산군·상품 구조·기초 개념

성향 제한을 받은 사용자
  → 진단과 분리된 학습 접근·가정 실험

이론을 숫자로 확인하려는 사용자
  → 메커니즘 시뮬레이션·전후 비교
```

아래쪽에 학습 범위를 작게 표시한다.

```text
주식 · 채권 · 펀드 · ETF · 부동산 · 금 · 선물 · 옵션 · 마진 · 레버리지
```

### 4. 사용자 여정

사용자 여정은 [플로우차트·와이어프레임 PPTX](FinMATE-플로우차트-와이어프레임.pptx)의 1~3번 슬라이드를 사용한다.

**화면에 넣을 것**

```text
로그인 → 진단 → 규칙 판정 → 근거 설명 → 상품 탐색
                         ↘
             개념 학습 → 퀴즈 → 시뮬레이션 → 포트폴리오 연습
```

**강조할 것**

- 진단 흐름과 학습 흐름이 분리되어 있다.
- AI는 성향을 판정하지 않고 근거를 설명한다.
- 학습과 시뮬레이션은 로그인 후에도 진단 등급과 독립적으로 접근한다.

### 5. 학습 구조

**화면에 넣을 것**

```text
자산군
  → 상품 구조
    → 메커니즘
      → 그림
        → 개념별 퀴즈
          → 시뮬레이션
            → 공식 자료 체크리스트
```

개념 카드 하나를 예시로 보여 준다.

```text
채권
  금리 변화 → 할인율 → 현재가격
  확인 문제 → 오답 이유
  시뮬레이션 → 듀레이션별 가격 변화
```

**말할 것**

“상품 이름을 외우는 대신 무엇이 결과를 바꾸는지 학습하도록 구성했습니다.”

### 6. Use Case와 요구사항

**화면에 넣을 것**

- Enterprise Architect로 만든 `UC-01-FinMATE-Overview` 이미지
- 옆에 작은 설명 3개
  - 일반 사용자: 진단·학습·실험
  - 내부 엔진: 규칙 판정·AI 설명·계산
  - 운영자: 출처·콘텐츠·데이터 검수

**하단 요약**

```text
FR: 사용자가 할 수 있는 기능
NFR: 보안·재현성·성능·출처·접근성·테스트 조건
```

모든 FR/NFR 목록을 한 슬라이드에 넣지 않는다. 대표 ID만 표시하고 상세 표는 부록으로 보낸다.

### 7. API와 시스템 구조

**화면에 넣을 것**

- [발표용 API 명세](FinMATE-발표용-API.yml)의 Swagger 캡처
- 태그별 API 그룹

```text
auth / assessments / products
learning
practice
```

**핵심 수치**

```text
25 paths · 26 operations
```

**말할 것**

“화면 기능을 하나의 거대한 API로 만들지 않고, 진단·학습·시뮬레이션·포트폴리오 연습으로 나눴습니다.”

대표 API만 보여 준다.

```text
POST /assessments
GET  /learning/concepts/{slug}/quiz
POST /learning/simulations/{scenarioId}/run
POST /practice/analyze
POST /practice/compare
```

### 8. 실제 화면과 와이어프레임

[플로우차트·와이어프레임 PPTX](FinMATE-플로우차트-와이어프레임.pptx)의 4~6번 슬라이드를 사용한다.

**보여 줄 화면**

- S1 로그인
- S2 진단 시작
- S3 질문 응답
- S4 결과·근거
- S5 카테고리 탐색
- S6 상품 상세

**화면 설명 규칙**

화면마다 다음 세 문장만 말한다.

```text
사용자 입력: 무엇을 입력하는가?
서버 처리: 어떤 API와 엔진이 처리하는가?
사용자 이해: 무엇을 확인하고 다음에 무엇을 하는가?
```

### 9. 모의투자 연습기

이 슬라이드가 발표의 고도화 핵심이다. [플로우차트·와이어프레임 PPTX](FinMATE-플로우차트-와이어프레임.pptx)의 7~8번 슬라이드를 사용한다.

**화면에 넣을 것**

- 개념 트리와 구조 그림
- 개념별 확인 문제
- 가상 상품 바구니
- 금리·가격·환율·비용 충격
- 손익·낙폭·자산별 기여도
- 결과의 의미와 한계

**말할 것**

“사용자는 상품을 주문하지 않고, 가정한 금리와 가격 충격을 넣어 결과가 어떻게 바뀌는지 확인합니다. 결과에는 계산 가정과 한계가 함께 표시됩니다.”

**반드시 표시할 것**

```text
교육용 계산
실제 시세 아님
미래 수익률 예측 아님
특정 상품 매매 권유 아님
```

### 10. 안전장치와 확장 계획

**왼쪽: 현재 안전장치**

- 규칙 엔진과 AI 역할 분리
- AI 실패 시 TEMPLATE 폴백
- 퀴즈 서버 채점
- 시뮬레이션 seed 재현
- 입력 가정·모델 버전·limitations 표시
- 실제 주문·계좌 연동 제외

**오른쪽: P1 확장**

- 공식 API·허용 문서 연동
- 기준일·지연·원문 URL·hash 저장
- 현재 자료와 과거 자료 탭 분리
- 로그인 후 진도·오답노트 저장
- 운영자 콘텐츠 검수·게시·만료

마지막 문장은 다음처럼 끝낸다.

“현재 구현은 교육용 가정값을 기반으로 하지만, 데이터 출처와 버전을 저장하는 구조로 확장할 수 있습니다.”

## 6. 발표에서 줄여야 하는 내용

- 모든 API의 요청·응답 필드 나열
- 59개 개념의 전체 목록
- 75개 퀴즈 문항 수를 성과처럼 강조하는 설명
- 아직 구현하지 않은 실시간 시세 연동을 현재 기능처럼 표현
- 복잡한 배포 도구 이름을 긴 시간 설명하는 내용

숫자는 범위를 증명할 때만 사용하고, 발표의 중심은 사용자 문제와 실제 동작으로 둔다.

## 7. 최종 발표 준비 순서

1. 본문 10장 순서로 슬라이드를 재배치한다.
2. Enterprise Architect에서 `UC-01-FinMATE-Overview`를 캡처한다.
3. [플로우차트·와이어프레임 PPTX](FinMATE-플로우차트-와이어프레임.pptx)의 필요한 슬라이드를 본문에 복사한다.
4. Swagger Editor에서 API 명세를 열고 `assessments`, `learning`, `practice` 화면을 캡처한다.
5. 각 슬라이드에 발표 문장을 한 줄만 남긴다.
6. 본문에서 P0와 현재 구현 범위를 설명하고, P1은 마지막 확장 계획으로 이동한다.
7. 발표 직전에는 S3 질문 제출 → S4 결과 → S7 개념 학습 → S9 포트폴리오 연습 순서로 시연한다.
