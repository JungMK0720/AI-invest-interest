## 1. 종합 판정

핵심 세로 슬라이스의 방향은 유효하다. 다만 기존 문서에는 초기 기획의 3단계 성향 모델과 현재 구현의 5단계 성향 모델이 함께 남아 있었고, AI 실패 정책도 문서와 구현이 달랐다. 따라서 **기획 문서 자체는 보완 후 조건부 통과**, 최종 제출물은 와이어프레임과 API 동작 검증을 마쳐야 통과로 판정한다.

현재 기준선은 다음과 같다.

| 영역 | 확정 기준 |
|---|---|
| 성향 판정 | 0~100점 가중 평균을 결정적 규칙 엔진으로 계산하고 5단계로 분류한다. `공격투자형 → 적극투자형 → 위험중립형 → 안정추구형 → 안정형` |
| 카테고리 위험도 | 예시 데이터의 내부 탐색용 1~6 등급. 숫자가 작을수록 고위험이다. 실제 금융상품의 법정 위험등급을 대체하지 않는다. |
| 카테고리 매칭 | 성향 등급과 위험등급을 비교하는 서비스 내부 필터이며, 투자 권유·적합성 판단을 수행하지 않는다. |
| AI 역할 | 성향 등급·점수·카테고리를 결정하지 않고, 결정 결과와 실제 답변을 바탕으로 설명 문장만 생성한다. |
| AI 장애 | LLM 설명 생성 실패 시 규칙 기반 템플릿으로 폴백하여 진단을 완료한다. 문항·카테고리 데이터가 준비되지 않은 경우에만 503을 반환한다. |
| 처리 방식 | MVP는 동기 처리다. 정상 응답은 `201 + COMPLETED`이며 `PROCESSING`과 `FAILED`는 비동기 확장 대비용 상태로 보관한다. |

## 2. 추적성 감사 결과

| 감사 항목 | 판정 | 감시자 의견 |
|---|---|---|
| P0 흐름 | 통과 | 로그인 → 질문 → 답변 → 규칙 판정/설명 → 카테고리 → 상품 상세가 연결된다. |
| 문서와 구현의 모델 일치 | 보완 완료 | 5단계 성향, 1~6 위험등급, `weight/score`, `reasoningSource`를 기준 문서에 반영한다. |
| API와 구현의 응답 일치 | 통과 | `AssessmentResult`, 상품 면책 문구, 카테고리 위험등급을 명세 기준으로 둔다. |
| AI 통제 경계 | 통과 | LLM이 등급을 바꾸지 못하도록 규칙 엔진을 선행하고, 설명 실패는 템플릿으로 대체한다. |
| 금융 표현 안전성 | 보완 필요 | `투자 권유 가능`, `적합성 원칙`을 서비스 내부 탐색 필터로 재정의한다. 외부 규제 준수 문구로 오인되지 않게 한다. |
| 예외 흐름 | 보완 필요 | AI 설명 폴백과 인프라/데이터 준비 실패를 분리한다. 사용자에게는 폴백 상태를 표시하고 내부 오류는 숨긴다. |
| 산출물 완료 | 부분 완료 | 실제 API 시나리오 검증(2026-09-08) 통과. S1~S6 와이어프레임 캡처만 남았다. |

## 3. P0에서 반드시 지킬 데이터 불변식

1. 활성 질문의 `weight` 합은 100이어야 한다.
2. 제출 답변은 활성 질문을 정확히 한 번씩 포함해야 한다.
3. 선택지는 제출된 `questionId`에 속해야 하며, 선택지 점수·배점은 외부 응답에 포함하지 않는다.
4. 성향 점수는 0~100, 성향 등급은 1~5 범위여야 한다.
5. 카테고리 위험등급은 1~6 범위여야 한다.
6. 추천 카테고리는 예시 상품이 하나 이상 있는 경우에만 노출하거나, 상품 없음 상태를 명시적으로 처리해야 한다.
7. P0 예시 데이터에서는 상품의 `risk_grade`와 소속 카테고리의 `risk_grade`를 일치시킨다. 향후 불일치를 허용하려면 매칭 기준을 별도로 정의한다.
8. 과거 진단 결과는 이후 질문·상품 시드 데이터가 바뀌어도 당시 결과와 설명을 재현할 수 있어야 한다.

## 6. 외부 기준에 대한 경계

이 프로젝트의 등급과 매칭식은 과제용 예시 서비스의 내부 모델이다. 금융투자협회 자료에는 투자자 성향 5단계 분류가 제시되고, 금융상품 위험도는 별도의 분류 체계로 다뤄지므로, 본 서비스의 단순 비교식을 실제 금융기관의 적합성·적정성 판단으로 표현하지 않는다. 실제 서비스화 전에는 최신 법령·규정과 상품별 공식 위험정보에 대한 별도 준법 검토가 필요하다.
